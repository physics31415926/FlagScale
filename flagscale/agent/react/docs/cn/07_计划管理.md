# 计划管理

## 概述

`TaskPlan` 提供步骤式计划管理，具备自动状态同步、一致性检查和重建建议功能。

## 数据模型

```python
Step（步骤）:
    title: str              # 步骤标题
    status: "todo" | "doing" | "done" | "failed" | "skipped"
    notes: str              # 备注
    started_turn: int       # 开始的轮次
    last_active_turn: int   # 最后活跃轮次
    failure_count: int      # 失败次数
```

## 核心功能

### 自动同步（`auto_sync_step`）
每次工具执行后调用：
- `write_file` 成功 → 标记相关步骤为 `done`
- 工具执行失败 → 增加 `failure_count`，将错误添加到 `notes`
- 无需 LLM 显式更新即可保持计划与实际执行同步

### 一致性检查（`check_consistency`）
每 5 轮运行一次：
- **停滞检测**：`doing` 状态超过 10 轮无活动 → 标记
- **重复失败**：`failure_count ≥ 3` → 标记需要更换方案
- 返回问题列表供 Agent 处理

### 重建建议（`should_rebuild`）
触发条件：
- 连续 3 次以上步骤失败
- 整体计划停滞（15 轮以上无步骤完成）
- 返回建议：创建新计划并采用不同方案

## 计划维护 Gate

`_check_plan_maintenance_gate`（软警告）：
- 当 `doing` 步骤 8 轮以上未更新时触发
- 注入提醒："步骤 X 已进行 N 轮——请更新或标记完成/失败"
- 防止计划悄然偏离现实

## 计划工具

| 工具 | 用途 |
|------|------|
| `plan_create` | 创建新计划及步骤 |
| `plan_update` | 更新步骤状态、添加备注 |
| `plan_status` | 显示当前计划状态 |

## 压缩集成

计划状态作为压缩锚点保留：
- 当前步骤标题和状态在上下文压缩中幸存
- 使用 `get('title')` 字段（修复了之前 `get('text')` 的 bug）
- 确保 Agent 在压缩后知道自己中断的位置
