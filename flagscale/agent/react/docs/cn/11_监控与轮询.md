# 监控与轮询

## 概述

监控和轮询系统处理长时间运行的操作，不消耗 LLM Token。它们在本地轮询，仅在发生有意义的事件时才返回给 LLM。

## MonitorTool

### 触发条件（满足任一即立即返回）
1. **错误模式**：匹配 `_INTERESTING_RE`（ERROR、FATAL、Traceback、OOM、NCCL 等）
2. **成功模式**：用户指定的正则匹配
3. **失败模式**：用户指定的正则匹配
4. **目标步数**：训练步数达到指定值
5. **进程死亡**：所有训练进程已退出（`pgrep` 检查）
6. **超时**：持续时间超限

### 进程死亡检测
- 通过 `pgrep -f <pattern>` 检查训练进程
- 默认模式：`torchrun|python.*train|flagscale|megatron|deepspeed`
- 首次轮询即检查——若进程已死亡，立即返回
- 结果标题：`TRAINING DEAD — all processes exited`

### Stderr 扫描
- 对 FlagScale 输出目录，自动发现 `stderr.log` 文件
- 追踪文件大小，仅检测新增错误（非已有内容）
- 过滤已知非错误：wandb 警告、FutureWarning、DeprecationWarning
- 结果标题：`TRAINING CRASHED — fatal error detected in stderr`

### 输出格式
```
TRAINING DEAD — all processes exited (3 polls, 15s)
Events:
  [process DEAD at start, no training running]
Last output before death:
  <日志最后 20 行>
```

### 参数

| 参数 | 类型 | 描述 |
|------|------|------|
| `file` | str | 要监控的日志文件路径 |
| `command` | str | 要轮询的 Shell 命令（替代 file） |
| `output_dir` | str | FlagScale 输出目录（自动扫描 stderr） |
| `duration` | int | 最大轮询秒数（默认 300） |
| `interval` | int | 轮询间隔秒数（默认 10） |
| `target_step` | int | 达到此训练步数时停止 |
| `success_pattern` | str | 正则——匹配时停止 |
| `fail_pattern` | str | 正则——匹配时停止 |
| `process_pattern` | str | 自定义 pgrep 模式用于存活检查 |

## PollMixin

提供 Agent 级别的轮询接口：
- 封装 MonitorTool 供 Agent 循环内使用
- 管理轮询期间的显示更新（进度指示器）
- 与 Gate 系统集成（Monitor Gate 连续 5 次阻断后自动解除）

## 与 Gate 系统的集成

- `_check_training_hang`：使用评分制（需 ≥2 个信号），非纯关键词匹配
- Monitor Gate 自动清除条件：
  - 连续 5 次阻断（防止永久卡死）
  - 诊断命令（pgrep/ps）返回空结果（进程已不存在）
